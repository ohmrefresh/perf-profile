# Skill: histogram_quantile

## MCP tool
`prometheus_mcp.query_range`

## Purpose
Compute latency percentiles from Prometheus histogram bucket metrics.
Used by: `latency-profile` agent.

## Tool call schema
Same as `query_range` skill — uses `query_range` endpoint with a
`histogram_quantile()` wrapped PromQL expression.

## PromQL pattern
```promql
histogram_quantile({{quantile}},
  sum(rate(http_server_requests_seconds_bucket{
    app_name="{{app_name}}",
    env_name="{{env_name}}"
  }[{{period}}])) by (uri, method, le)
)
```

## Required metric
`http_server_requests_seconds_bucket` with labels:
- `app_name` — application identifier
- `env_name` — environment
- `uri` — request path (normalized)
- `method` — HTTP method
- `le` — histogram upper bound (auto-generated by Micrometer)

## Micrometer Spring Boot config (reference)
```yaml
management:
  metrics:
    tags:
      app_name: ${APP_NAME:payment-api}
      env_name: ${ENV_NAME:local}
    distribution:
      percentiles-histogram:
        http.server.requests: true
      slo:
        http.server.requests: 50ms, 100ms, 200ms, 500ms, 1000ms
```

## Response handling
- Prometheus returns `NaN` when a route has zero traffic in the window → treat as `null`.
- Convert seconds to ms: `value_ms = parseFloat(value) * 1000`.
- Round to nearest integer.

## Concurrency
Counts as **1 slot** per quantile query. If fetching p50+p95+p99 separately,
that is 3 slots. Prefer a single query per quantile; orchestrator batches them.
